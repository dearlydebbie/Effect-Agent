# Lens Studio MCP

## Current verified connection

Effect Lab communicates with the official local MCP server generated by Lens Studio. During the 14 August 2026 milestone, Lens Studio 5.23.1 reported `Lens Studio MCP Server` 1.0.0 and 38 tools. This is a verification snapshot, not a permanent capability list.

The app uses the standard MCP sequence:

1. Send `initialize`.
2. Send `notifications/initialized`.
3. Read `tools/list`.
4. Map only the exact returned tool names.
5. Call a mapped tool through `tools/call`.

## Local setup

1. Open Lens Studio.
2. Open the Lens project that Effect Lab may inspect or change.
3. In Lens Studio, select **AI Assistant → AI Model Context Protocol (MCP) → Configure Server → Copy MCP Config**.
4. Run `pbpaste | npm run lens:sync:manual:sandbox` from the Effect Lab directory.
5. Restart `npm run dev`.
6. Open Settings.
7. Select **Test connection**.
8. Select **View capabilities** to inspect the live result.

The manual sync command reads the copied JSON from stdin. The token does not appear in shell history. The command initializes MCP, reads the live capability list, and reads the current project identity before it writes ignored `.env.local` with owner-only permissions. It never prints the credential. The HTTP transport accepts only a loopback host.

`npm run lens:sync` keeps automatic disk discovery as an optional convenience. It also checks existing local credentials. It never selects a candidate only because its file is newer. Every candidate must answer live MCP requests. Multiple live candidates require manual sync.

## Soft Flash Test

The first controlled recipe uses only tools seen in the verified discovery response:

- `QueryRuntimeSceneTool` inspects the runtime scene.
- `scene-graphql` confirms the built-in preset and creates one scene object.
- `RecompileTypeScriptTool` runs the compile check.
- `RunAndCollectLogsTool` reads preview runtime logs.
- `PreviewPanelTool` captures preview evidence.

The recipe uses the discovered `BlownWhitePreset` to create one `PostEffectVisual` treatment. It avoids face-shape changes and heavy smoothing. The Studio job displays the full specification and requires confirmation before the mutation call. The orchestrator can retry compilation at most twice. It stops at `NEEDS_REVIEW`.

After technical QA, Effect Lab captures the actual Preview panel image. The preview is the required input for Visual QA. A successful compile does not make Visual QA pass. If no real `VisionProvider` is configured, the app shows the image, returns `UNAVAILABLE`, keeps visual scores null, and continues to human review.

Experience QA is separate because one preview cannot prove timing, interaction response, reset behaviour, or the absence of dead ends. Missing evidence stays `UNKNOWN`.

## Supported and unsupported work

Effect Lab currently supports connection testing, capability inspection, one reviewed Soft Flash recipe, compilation checks, runtime log checks, scene verification, and a preview capture.

It also stores local iteration evidence and human feedback. Visual iteration plans are capped at three and must pass through the existing confirmation gate before any Lens Studio mutation. No visual change is applied when Visual QA is unavailable.

Technical iteration planning is read-only. It queries the live runtime hierarchy, reads the matching editor component, and resolves material and texture assets before displaying a proposed operation. The planner stores discovered IDs and readable property values as the Iteration 0 baseline. It does not use `VirtualScene read`, because that command writes a snapshot file into the Lens project. It does not map undocumented raw parameters to visual recommendations. In the current Soft Flash project, inspection resolves `Blown White` → `PostEffectVisual` → `Color Correction.mat` → `BlownWhite.png`; it does not expose a documented independent flash, highlight, or skin-texture control.

It does not publish or submit a Lens. It does not control a Snapchat account. It does not run arbitrary generated editor code. It does not assume a tool exists because a previous Lens Studio version exposed it. TikTok remains a manual Effect House build-pack workflow.

## Failure handling

If the connection is unavailable, open Lens Studio and the required project. Copy the MCP config. Run `pbpaste | npm run lens:sync:manual:sandbox`. Restart Effect Lab. If the port or token changes, sync again. A missing server, authorization error, project mismatch, missing capability, compile failure, or runtime error leaves the job waiting or failed and does not attempt publishing.
